# CLAUDE.md

Guidance for Claude Code (and other AI coding assistants) working in this repository.

## Project Overview

**NASC Grievance Portal** — a Flutter app for campus complaint/grievance management at Nehru Arts and Science College. Teachers report maintenance issues with photos and track status; admins triage, assign, resolve, and merge duplicates. A booking module for venues/resources is partially built.

## Commands

- Get dependencies: `flutter pub get`
- Run the app: `flutter run`
- Run tests: `flutter test`
- Analyze/lint: `flutter analyze`
- Format code: `dart format lib test`
- Deploy Firestore indexes: `firebase deploy --only firestore:indexes`

## Architecture

- **Entry point:** `lib/main.dart` — initializes Firebase, then shows `LoginScreen`.
- **Routing:** manual `Navigator.push` between screens (no named routes, no router package).
- **State management:** plain `StatefulWidget` + `setState`. No provider/bloc/riverpod.
- **Firebase access:** `firebase_core`, `firebase_auth`, `cloud_firestore` used directly (no repository layer).
- **Image upload:** Cloudinary via `http` MultipartRequest in `lib/services/cloudinary_service.dart`.

## Key Conventions

- **Material 3**, seed color `0xFF0F766E` (teal). Theme colors live in `lib/utils/app_colors.dart` — use `AppColors.*` instead of hardcoded hex in screens that already use it (note: booking screens and teacher/admin homes mix in some hardcoded `Color(0xFF...)` values — prefer `AppColors` for new code).
- **Firestore field names must match exactly** between writer and reader screens. The `complaint_model.dart` header comments stress this: field names in `new_complaint_screen.dart` writes must equal what `my_complaints_screen.dart` / `admin_*` screens read.
- **Complaint fields** (Firestore `complaints` collection):
  `reporterUid`, `category`, `priority` (`low`/`medium`/`high`), `status` (`pending`/`in_progress`/`resolved`/`merged`), `block`, `floor`, `room`, `description`, `photoUrls`, plus optional `assignedTechnician`, `internalNotes`, `closureNotes`, `proofPhotoUrl`, `mergedInto`, `createdAt` (server timestamp).
- **Booking fields** (Firestore `bookings` collection, read side): `bookedByUid`, `status` (`pending`/`approved`/`completed`), `purpose`/`title`, `createdAt`.
- **User fields** (Firestore `users` collection): `fullName`, `staffId`, `department`, `designation`, `email`, `mobile`, `role` (`teacher`/`admin`), `createdAt`.
- **Admin secret key** is hardcoded in `lib/screens/register_screen.dart` (`NASC2024ADMIN`) — note it is beginner-friendly and should be moved server-side for production.
- **Comments style:** existing code uses extensive explanatory comments in plain language. Keep them, and match the tone when adding code.

## Gotchas / Warnings

1. **Composite indexes required** — `firestore.indexes.json` declares two indexes on `complaints` (reporterUid+createdAt; block+category). New queries combining two fields will fail at runtime until an index is deployed. Update `firestore.indexes.json` when adding such queries.
2. **Booking write is a placeholder** — `new_booking_screen.dart` `_submit()` only shows a snackbar and does NOT write to Firestore, while `booking_ticket_screen.dart` and `booking_dashboard_screen.dart` DO read from `bookings`. Writing the booking document is an obvious next feature — use `bookedByUid` + `status: 'pending'` + `purpose` + `createdAt` so existing readers work.
3. **Status values:** complaint status strings are `pending`, `in_progress`, `resolved`, and `merged` (admin duplicate screen). `my_complaints_screen.dart` filters use `pending`/`in_progress`/`resolved` only.
4. **Priority seeding in triage** — `admin_triage_screen.dart` intentionally seeds `_selectedPriority` from Firestore exactly once (`_priorityInitialized` flag + `addPostFrameCallback`). Do not "simplify" this back into build-time mutation; it caused a real bug.
5. **Images are compressed client-side** before Cloudinary upload (`minWidth/minHeight 1024`, quality 70 in `new_complaint_screen.dart`).
6. **`firebase_options.dart` is generated** — regenerate with `flutterfire configure`, don't edit by hand.
7. **Max content width:** teacher screens wrap content in `ConstrainedBox(maxWidth: 480)`, admin screens use `maxWidth: 700`. Keep this pattern for new screens.

## Testing

- `test/widget_test.dart` is the stock counter smoke test and does **not** match the app (it references a counter that doesn't exist). It will fail on `MyApp` pump. Replace with meaningful widget tests when adding coverage.
- `flutter test` currently expects a working Firebase setup at startup because `main.dart` calls `Firebase.initializeApp`; tests should inject mocks or use `Firebase.initializeApp` with test options.

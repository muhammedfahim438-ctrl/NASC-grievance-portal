# Backend Info — NASC Grievance Portal

Technical documentation of the backend services powering the app: **Firebase** (Authentication + Cloud Firestore) and **Cloudinary** (image hosting).

---

## 1. Overview

The app has **no traditional backend server**. All backend functionality is provided by Google's Firebase BaaS (Backend-as-a-Service) plus Cloudinary for image delivery.

```
Flutter App
   │
   ├── Firebase Auth          → email/password login & registration
   ├── Cloud Firestore        → users, complaints, bookings data
   └── Cloudinary             → complaint photos + resolution proof images
```

### 2.3 Firebase Authentication

Handled by `lib/services/auth_service.dart` wrapping `firebase_auth`:

| Method | What it does | Errors translated to |
| --- | --- | --- |
| `signIn(email, password)` | Email/password login | "No account found with this email." / "Incorrect password." etc. |
| `signUp(...)` | Creates Auth user, then writes profile doc to `users/{uid}` | "An account already exists with this email." etc. |
| `getUserRole(uid)` | Reads `role` field from `users/{uid}` to route to Teacher or Admin home | null on failure |
| `signOut()` | Signs the user out | — |

**Role-based redirect:** after a successful `signIn`, `login_screen.dart` calls `getUserRole` and pushes either `TeacherHomeScreen` (`role == 'teacher'`) or `AdminHomeScreen` (`role == 'admin'`).

### 2.4 Cloud Firestore — Data Collections

#### `users`
One document per registered user (document ID = Auth `uid`).

| Field | Type | Written by |
| --- | --- | --- |
| fullName | string | `auth_service.dart` signUp |
| staffId | string | signUp |
| department | string | signUp (cs / cs_ds / aiml / bca / others) |
| designation | string | signUp (staff / admin) |
| email | string | signUp |
| mobile | string | signUp |
| role | string | signUp (`teacher` / `admin`) |
| createdAt | timestamp | signUp (server time) |

#### `complaints`
One document per complaint ticket. Document ID doubles as the **ticket number** (screens display the first 6 chars uppercased).

| Field | Type | Written by | Read by |
| --- | --- | --- | --- |
| reporterUid | string | `new_complaint_screen.dart` | My Tickets, Admin list |
| category | string | new complaint | everywhere |
| priority | string (`low`/`medium`/`high`) | new complaint; triage updates | everywhere |
| status | string (`pending`/`in_progress`/`resolved`/`merged`) | new complaint, triage, resolution, duplicate merge | everywhere |
| block | string | new complaint | everywhere |
| floor | string | new complaint | everywhere |
| room | string | new complaint | everywhere |
| description | string | new complaint | everywhere |
| photoUrls | string[] (Cloudinary URLs) | new complaint | details, triage, resolution |
| assignedTechnician | string (optional) | triage `_assignTicket` | admin |
| internalNotes | string (optional) | triage `_assignTicket` | admin |
| closureNotes | string (optional) | resolution `_confirmAndClose` / `_requestRework` | admin |
| proofPhotoUrl | string (optional) | resolution `_confirmAndClose` | admin |
| mergedInto | string (optional) | duplicate screen `_mergeSelected` | admin |
| createdAt | timestamp (server) | new complaint | My Tickets (ordering), details |

#### `bookings`
Read by `booking_ticket_screen.dart` and `booking_dashboard_screen.dart`. **Currently nothing writes to this collection** — see the "Known Gap" note below.

| Field | Type | Notes |
| --- | --- | --- |
| bookedByUid | string | Filter for the user's bookings |
| status | string (`pending`/`approved`/`completed`) | Displayed as a badge |
| purpose (or `title`) | string | Event/occasion name |
| createdAt | timestamp | Required for `orderBy` in `booking_ticket_screen.dart` |

### 2.5 Queries & Composite Indexes

Two composite indexes are required (declared in `firestore.indexes.json`). **Any new two-field query needs an index deployed or it will fail at runtime.**

| Collection | Fields | Used by |
| --- | --- | --- |
| complaints | `reporterUid` ASC + `createdAt` DESC | `my_complaints_screen.dart` |
| complaints | `block` ASC + `category` ASC | `admin_duplicate_screen.dart` |

Deploy with:
```bash
firebase deploy --only firestore:indexes
```

### 2.6 Firestore Security Rules

**Not yet defined in this repository** (there is no `firestore.rules` file). For production this is a priority — define rules that at minimum:
- Allow users to read/write only their own `users/{uid}` doc.
- Allow users to create complaints with their own `reporterUid` and read only their own complaints.
- Restrict `complaints` writes (status changes, assignments, merges) to admins.

## 3. Cloudinary

Used to host complaint photos and resolution proof images.

### 3.1 Configuration (`lib/services/cloudinary_service.dart`)

```dart
static const String _cloudName = 'awmitzkw';
static const String _uploadPreset = 'nasc_complaints';
```

- **Upload endpoint:** `https://api.cloudinary.com/v1_1/awmitzkw/image/upload`
- **Auth model:** unsigned upload using the `upload_preset` (no API secret stored in the app).
- **Protocol:** HTTP `MultipartRequest` (`package:http`).

### 3.2 Upload Flow

```
Teacher picks photo → image_picker (quality 85)
   → flutter_image_compress (minWidth/minHeight 1024, quality 70)
   → CloudinaryService.uploadImages() uploads each image
   → returns secure_url list → stored in complaints.photoUrls
```

`uploadImages` uploads images one by one; failures are skipped (the complaint still saves).

### 3.3 Files uploaded

| Caller | Filename pattern |
| --- | --- |
| `new_complaint_screen.dart` | `complaint_<epoch_ms>_<index>.jpg` |
| `admin_resolution_screen.dart` | `proof_<epoch_ms>.jpg` |

## 5. Backend Gaps & Recommendations

1. **Bookings not persisted** — `new_booking_screen.dart` `_submit()` is a placeholder snackbar. Write the doc with `bookedByUid`, `status: 'pending'`, `purpose`, `createdAt` so the existing readers work.
2. **Firestore security rules missing** — add `firestore.rules` before any production deploy.
3. **Admin secret key hardcoded** (`NASC2024ADMIN` in `register_screen.dart`) — move to a Cloud Function / server-side check.
4. **Forgot password not wired** — `login_screen.dart` has a placeholder button; add `sendPasswordResetEmail`.
5. **Cloudinary unsigned preset** — fine for a learning project; switch to signed uploads (server-side signature) for production.
6. **Booking admin side** — no admin screen to approve bookings; statuses `approved`/`completed` are counted but never set by any screen.
